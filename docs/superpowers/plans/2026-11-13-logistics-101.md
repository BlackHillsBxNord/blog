# Logistics 101 First Post Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Logistics section to the MkDocs blog and publish its first post, *Logistics 101*, teaching the field through a security/evasion lens.

**Architecture:** Pure content change. New `docs/logistics/` section (index stub + post), one `mkdocs.yml` nav edit. No code, no plugins — uses the Material theme features already configured (admonitions, details, tags).

**Tech Stack:** MkDocs + Material for MkDocs; Markdown only.

**Spec:** `docs/superpowers/specs/2026-11-13-logistics-101-design.md`

## Global Constraints

- Analysis of publicly documented schemes only (DOJ, OFAC, UN reporting) — case-analysis tone, never an evasion how-to.
- Section index stubs match the existing style: `# Title` + one-line description.
- Nav order: `Logistics` goes between `Research` and `Tags`.
- Post tags: `logistics`, `sanctions-evasion`, `osint` (via the tags plugin's page metadata).
- Post length: ~1,200–1,800 words.

## Review Focus

1. **Broken build from bad nav path** — nav entry must match the file path exactly; `mkdocs build --strict` catches it.
2. **Abuse blocks reading as instructions** — every "how it gets abused" block must cite/attribute a public case or report; no step-by-step operational detail beyond what's public.
3. **Tags not rendering** — tags plugin requires the `tags` key in page metadata; a typo silently drops the post from tags.md. Verify post appears on the Tags page.
4. **Admonition/details syntax errors** — Material admonitions need exact `!!!`/`???` prefixes; build succeeds even when they render as plain text, so verify visually in the built HTML.
5. **Section stub inconsistent with siblings** — index.md must mirror the other five sections' format so the homepage/section pages stay uniform.
